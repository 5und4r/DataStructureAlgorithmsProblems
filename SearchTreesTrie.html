Why search trees?

A sorted array finds things fast but is slow to insert into. A linked list inserts fast but searches slowly. A binary search tree gives you both — as long as it stays balanced. AVL and Red-Black trees are BSTs that rebalance themselves automatically. A trie is a different kind of tree built specially for strings.

Binary search tree (BST)

  • Each node has at most two children: left and right.
  • BST rule: every key in the left subtree is smaller, every key in the right subtree is larger.
  • Search: compare with the node; go left if smaller, right if larger. Each step discards a whole subtree.
  • Insert: search for the key; the empty spot where the search ends is where the new node goes.
  • Inorder traversal (left, node, right) prints the keys in sorted order.
  • All operations cost O(h), where h is the height of the tree.

The balancing problem

  • Insert keys in sorted order into a plain BST and every node goes to the right — the tree becomes a linked list.
  • Height becomes n, so search, insert and delete slow down to O(n).
  • A balanced tree keeps height close to log₂ n: 1,000,000 keys need only about 20 comparisons.
  • Self-balancing trees (AVL, Red-Black) check a rule after every insert or delete and repair the shape with rotations.
  • A rotation is a small, local pointer change that keeps the BST order but changes the height.

Deleting from a BST

  • Leaf: just remove it.
  • One child: the child takes the deleted node's place.
  • Two children: copy in the inorder successor (smallest key on the right side), then delete that successor.

AVL tree

  • Named after inventors Adelson-Velsky and Landis (1962) — the first self-balancing BST.
  • Balance factor = height(left subtree) − height(right subtree).
  • AVL rule: every node's balance factor must be −1, 0 or +1.
  • After inserting, walk back up updating heights. The first node with ±2 is fixed by one of four rotation cases.
  • Height stays below about 1.44 log₂ n — the most tightly balanced common BST, so lookups are very fast.
  • Trade-off: stricter balance means slightly more rotation work on inserts and deletes.

Red-Black tree

Every node is painted red or black. Five rules keep the tree roughly balanced:

  1. Every node is either red or black.
  2. The root is always black.
  3. Every empty child (NIL) counts as black.
  4. A red node never has a red child — no two reds in a row.
  5. Every path from a node down to its NIL leaves has the same number of black nodes (its black-height).
  • Together these guarantee height ≤ 2 log₂(n + 1).
  • New nodes are inserted red. If the parent is also red, look at the uncle: red uncle → recolour; black uncle → rotate (and recolour).
  • Looser than AVL, so it does fewer rotations — at most 2 per insert. That is why std::map and std::set use it.

Trie (prefix tree)

  • A tree for strings. Each edge stands for one character; the path from the root spells a prefix.
  • Words with a common start share nodes: tea and ten share “te”.
  • Each node has up to 26 children (for a–z) and an isEnd flag that marks a complete word.
  • Insert / search cost O(L), where L is the word length — independent of how many words are stored.
  • Prefix queries are the superpower: walk to the prefix node, then everything below it starts with that prefix.
  • Trade-off: uses more memory than a hash set because of the child pointers.
