Two Big Ideas for Designing Algorithms

Most efficient algorithms follow a strategy. Greedy algorithms grab the best-looking option at every step and never look back. Divide & Conquer algorithms break a big problem into smaller copies of itself, solve them, and combine the answers. Dijkstra, Prim and Kruskal are all greedy — and Kruskal leans on sorting, a classic divide-and-conquer task.

🪙 Greedy Method

“Take the best choice right now and commit to it.”

A greedy algorithm builds a solution piece by piece. At each step it picks the option that looks best locally, hoping this leads to the best global answer. It never undoes a choice, which makes it fast and simple.

🎯
Greedy-choice property

A locally best choice is part of some optimal solution.

🧩
Optimal substructure

The optimal answer contains optimal answers to sub-problems.

⚡
No backtracking

Each decision is final → usually very fast.

Template: while (not done) { pick best candidate; if (feasible) add it; }

✂️ Divide & Conquer

“Split it, solve the small pieces, glue the answers.”

The problem is split into smaller sub-problems of the same type, each solved recursively, and their results are combined. Running time is described by a recurrence such as T(n) = 2T(n/2) + O(n).

🔪
Divide

Break the problem into smaller sub-problems.

🧠
Conquer

Solve each recursively (tiny ones directly).

🧷
Combine

Merge sub-answers into the final answer.

🧭Shortest Path vs Minimum Spanning Tree

Shortest path (Dijkstra) answers: “What is the cheapest route from my source to every other place?” The result is a tree of routes rooted at the source.

Minimum Spanning Tree (Prim, Kruskal) answers: “What is the cheapest set of edges that connects every vertex?” It has exactly V − 1 edges, no cycles, and minimum total weight — there is no source. All three demos use the same 6-vertex graph so you can compare the results directly.
