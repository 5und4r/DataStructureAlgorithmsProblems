The big picture

Trees and graphs model anything made of things (nodes) and connections (edges): cities and roads, people and friendships, folders and files. A traversal is simply a systematic way to visit every node exactly once.

What is a tree?

  • A hierarchical structure: one special node at the top called the root.
  • Every node except the root has exactly one parent; a node can have many children.
  • Nodes with no children are leaves; others are internal nodes.
  • With n nodes there are always exactly n − 1 edges, and there are no cycles.
  • Depth of a node = edges from the root to it. Height of the tree = deepest level.
  • A binary tree lets each node have at most two children: left and right.
  • A Binary Search Tree (BST) keeps left < node < right, which makes searching fast.

What is a graph?

  • A graph G = (V, E) is a set of vertices V joined by edges E.
  • Undirected: edges go both ways (friendship). Directed: edges have a direction (follows on social media).
  • Weighted: edges carry a cost such as distance or time.
  • Graphs may contain cycles and may be disconnected — unlike trees.
  • A tree is a special graph: connected and acyclic.
  • Degree of a vertex = number of edges touching it.
  • Because of cycles, graph traversals need a visited array so no node is processed twice.

Two ways to explore

BFS — ripples in water
DFS — a maze explorer
  • BFS visits all neighbours first, then their neighbours — level by level, using a queue.
  • DFS follows one path as deep as possible, then backtracks, using recursion or a stack.

Breadth-first search

BFS explores a graph in waves: first the start node, then everything 1 edge away, then 2 edges away, and so on. The d= badge on each node shows its distance from the start.

1. Start

Mark the source visited and push it into an empty queue.

2. Dequeue

Take the node at the front of the queue and process it.

3. Enqueue neighbours

Every unvisited neighbour is marked visited and pushed to the back.

4. Repeat

Continue until the queue is empty. Each node enters the queue once.

Depth-first search

DFS keeps walking to an unvisited neighbour until it gets stuck, then backtracks to the most recent node that still has unexplored neighbours. The # badge shows the order in which nodes were discovered.

1. Visit

Mark the current node visited and print it.

2. Go deeper

For the first unvisited neighbour, call DFS on it immediately.

3. Skip visited

Neighbours already visited are ignored, which prevents loops.

4. Backtrack

When no neighbours remain, return to the caller and continue there.

Problem-solving techniques

Most tree and graph questions become easy once you recognise them as a traversal plus a little extra bookkeeping. Use this recipe, then match the question to a pattern.

1

Model it

What are the nodes? What makes an edge? Grids, words and states are graphs too.

2

Store it

Build an adjacency list. For grids, use the four neighbour directions.

3

Pick a traversal

Nearest or fewest steps → BFS. Explore everything or structure → DFS.

4

Track extra state

visited, dist, parent, colour, component id — whatever the answer needs.

5

Check edge cases

Disconnected parts, single node, self-loops. Confirm O(V + E).

Common mistakes to avoid

  • In BFS, mark a node visited when you push it, not when you pop it — otherwise it can enter the queue many times.
  • For a disconnected graph, loop over every node and start a new traversal from each unvisited one.
  • In an undirected graph, the edge back to your parent is not a cycle.
  • Very deep recursion can overflow the stack — switch to an explicit stack for huge inputs.
  • Reset visited between test cases.
