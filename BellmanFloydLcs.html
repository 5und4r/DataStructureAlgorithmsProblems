Bellman–Ford Algorithm 🧭

Finds the shortest distance from one source vertex to every other vertex in a weighted directed graph — even when some edges have negative weights — and tells you if a negative cycle makes "shortest" meaningless.

Single-source shortest pathsNegative edges allowedNegative-cycle detectionDynamic programming flavour

💡The big idea

Imagine you stand in city S and want the cheapest fare to every other city. Some routes even give you cashback (negative cost), so greedy shortcuts don't work.

Bellman–Ford is patient: it checks every road, again and again. In each round, good news travels one more road away from S. A shortest route never needs more than V − 1 roads, so V − 1 rounds are always enough.

🔧The key move: relaxation

if d[u] + w(u,v) < d[v] : d[v] ← d[u] + w(u,v) // found a cheaper way π[v] ← u // remember we came from u
u
3
── w = −2 ──▶
v
5 → 1

3 + (−2) = 1 < 5, so v's distance improves from 5 to 1.

🪜Step by step

  1. Initialise: d[source] = 0, every other d[v] = ∞, parents π empty.
  2. Repeat V − 1 times: go through all edges (u, v, w) and relax each one.
  3. Early stop (optional): if a full pass changes nothing, the answer is already final.
  4. Check: scan all edges once more. If any edge can still be relaxed → negative cycle.
  5. Read the answer: d[v] is the shortest distance; follow π[v] backwards to get the path.

🤔Why V − 1 passes? Why the extra check?

A shortest path visits each vertex at most once, so it has at most V − 1 edges. After pass k, every shortest path that uses ≤ k edges is correct. So after V − 1 passes, all are correct.

If a cycle has a negative total weight (e.g. T → X → T = 5 + (−8) = −3), you could loop forever and the cost keeps falling. That's why one extra pass that still finds an improvement proves a negative cycle exists.

O(V·E)Time
O(V)Space
O(E)Best case (early stop)

🌍Where is it used?

📡
Network routing (RIP)

Distance-vector routers share tables with neighbours — that is Bellman–Ford running across the internet.

💱
Currency arbitrage

Use −log(exchange rate) as weights. A negative cycle = a sequence of trades that makes money.

🗓️
Scheduling constraints

Systems like "task B starts ≤ 3 h after A" become graphs; Bellman–Ford finds a valid timetable.

⚡
Johnson's algorithm

Uses Bellman–Ford once to re-weight edges so Dijkstra can run on graphs with negative edges.

🎮
Games & economies

Paths with rewards (negative costs), and detecting infinite-reward loops in game design.

🚚
Logistics with rebates

Delivery routes where some legs earn credits or subsidies, giving negative costs.

Floyd–Warshall Algorithm 🗺️

Computes the shortest distance between every pair of vertices at once. The whole algorithm is three nested loops over a distance matrix — short to code and easy to picture.

All-pairs shortest pathsDynamic programmingWorks with negative edgesMatrix based

💡The big idea

Think of an airline building a fare chart between all airports. First it only knows direct flights. Then it asks airport 1: "Would any trip i → j be cheaper with a stop-over at you?" Then airport 2, airport 3, …

After every airport has been tried as a stop-over, every entry in the chart is the cheapest possible trip. Each round only needs the table from the previous round — classic dynamic programming.

🧮The recurrence

D(k)[i][j] = min( D(k-1)[i][j] , D(k-1)[i][k] + D(k-1)[k][j] ) // best i→j using only stops {1..k} // either skip k, or go i → k → j
D(0) is the adjacency matrix: 0 on the diagonal, the edge weight if an edge exists, ∞ otherwise.

🪜Step by step

  1. Build D: D[i][i] = 0, D[i][j] = w(i, j) if an edge exists, otherwise ∞.
  2. For k = 1 … n (the allowed stop-over vertex):
  3. For every pair (i, j): if D[i][k] + D[k][j] < D[i][j], replace D[i][j] with it.
  4. Negative cycle? If any D[i][i] < 0 after the loops, a negative cycle exists.
  5. Paths: keep a next[i][j] table to rebuild the actual route.
⚠ The k loop must be the outermost. Rows and columns of k never change during round k, so one matrix can be updated in place.

⏱️Complexity

O(V³)Time
O(V²)Space

Best for dense or small/medium graphs (a few hundred vertices). For sparse graphs, running Dijkstra from every vertex can be faster.

🆚Compared with Bellman–Ford

Bellman–Ford answers "from one source". Floyd–Warshall answers "from every source" in one go. Running Bellman–Ford V times would cost O(V²·E), which is O(V⁴) on dense graphs — Floyd–Warshall's O(V³) is better.

👥

Degrees of separation and closeness between all pairs of people.

🌐

💱

Longest Common Subsequence 🧬

Given two sequences, find the longest sequence of characters that appears in both, in the same order — the characters do not have to be next to each other.

Dynamic programmingOptimal substructureOverlapping subproblemsTraceback

🔤Subsequence vs substring

From ABCDE, keep the order but you may skip letters:

ABCDE

ACE is a subsequence (gaps allowed). BCD is a substring (must be contiguous). Every substring is a subsequence, but not the other way round.

For X = ABCBDAB and Y = BDCABA, one LCS is BCBA (length 4). BDAB and BCAB are also valid — an LCS need not be unique.

💡The big idea

Look at the last characters of both strings:

✅ They match → that character is in the LCS. Remove it from both and solve the smaller problem.

❌ They differ → at least one of them is not in the LCS. Try dropping the last char of X, then of Y, and keep the better answer.

Brute force checks all 2m subsequences. DP stores each sub-answer once in a table, so the work is just m × n.

🧮The recurrence

L[i][j] = length of LCS of X[1..i] and Y[1..j] L[i][j] = 0 if i = 0 or j = 0 = L[i-1][j-1] + 1 ↖ if X[i] = Y[j] = max(L[i-1][j], L[i][j-1]) ↑ ← otherwise
Each cell needs only three neighbours: top-left ↖, top ↑ and left ←. So we fill the table row by row.

🪜Step by step

  1. Make a table of size (m+1) × (n+1). Row 0 and column 0 are all 0.
  2. Fill row by row using the rule: match → diagonal + 1; else max(top, left).
  3. Read the length in the bottom-right cell L[m][n].
  4. Trace back from L[m][n]: on ↖ take the character and go diagonally; otherwise move ↑ or ←.
  5. Reverse the collected characters — that is the LCS.

⏱️Complexity

O(m·n)Time
O(m·n)Space (with traceback)
O(min(m,n))Space (length only)

If you only need the length, keep just two rows of the table.

🧩Why is it DP?

Optimal substructure: the LCS of two strings is built from the LCS of their prefixes.

Overlapping subproblems: the same prefix pair (i, j) is needed again and again — the table computes each once.

🌍Where is it used?

Shows which lines changed between two file versions — the unchanged lines are the LCS.

🧬
Bioinformatics

Compares DNA and protein sequences to measure similarity between genes and species.

🕵️
Plagiarism detection

Long common subsequences of words or code tokens signal copied work.

✍️

🔄
File sync & merge

🎙️
