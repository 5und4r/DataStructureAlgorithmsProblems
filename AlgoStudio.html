Greedy Fractional Knapsack

Greedy method O(n log n)Optimal for fractional items
Capacity (kg) Green = taken fully · Amber = taken partly · Faded = skipped
🎒

A thief, a bag and a choice

A thief has a bag that can carry W kg. There are items like gold dust, silver dust and spices — each with a weight and a value — and they can be divided. Which pieces should go in the bag to carry home the maximum value? The greedy answer: always take what gives the most value per kg.

💡 Key Idea

For each item compute its profit density:
ratio(i) = value(i) / weight(i)
Sort items by ratio (highest first). Keep taking whole items while they fit. When the next item does not fit, take just the fraction that fills the bag exactly. Stop.

🪜 Step by Step

  1. Read n items (weight, value) and capacity W.
  2. Compute value/weight for every item.
  3. Sort items in decreasing order of ratio.
  4. For each item: if weight ≤ remaining capacity → take it all.
  5. Otherwise take fraction = remaining / weight, and stop.
  6. Sum the values taken → maximum profit.

📝 Worked Example (W = 60)

Itemwvv/wTaken
📷 Camera151057.0100% → 105
🥇 Gold10606.0100% → 60
🥈 Silver201005.0100% → 100
💻 Laptop301204.050% → 60

Total = 105 + 60 + 100 + 60 = 325

⏱ Complexity & Why it works

  • Sorting: O(n log n); filling: O(n) → overall O(n log n).
  • Space: O(1) extra (besides input).
  • Greedy-choice property: any optimal solution can be changed to include as much of the highest-ratio item as possible without losing value — swapping a kg of lower ratio for a kg of higher ratio never hurts.
  • Optimal substructure: after taking the best item, the rest is a smaller knapsack problem.

Limitations of the Greedy Method

Locally best ≠ globally best Greedy vs Dynamic Programming
Scenario: Orange = Greedy · Purple = Optimal (DP)
🧗

The mountain-climber trap

A climber who always steps to the highest nearby rock may reach a small hill and get stuck, never seeing the taller mountain behind. Greedy algorithms make the best local choice and never go back. That is fast — but sometimes wrong.

🚫 Main Limitations

  • No backtracking: once a choice is made it is never undone.
  • Local optimum trap: a sequence of best-looking moves can miss the global optimum.
  • Works only for special problems — those with the greedy-choice property and optimal substructure.
  • Correctness is hard to prove: each greedy algorithm needs its own proof (exchange argument).
  • Choice of greedy criterion matters: by value? by weight? by ratio? A wrong criterion gives wrong answers.

🎒 0/1 Knapsack counter-example

Capacity 50: X(w10, v60, r6), Y(w20, v100, r5), Z(w30, v120, r4)
Greedy by ratio → X + Y = 160 Optimal (DP) → Y + Z = 220 ✔
Items cannot be broken, so the leftover 20 kg is wasted. Greedy works for fractional knapsack but not for 0/1 knapsack.

🪙 Coin change counter-example

Coins {1, 3, 4}, amount 6:
Greedy → 4 + 1 + 1 = 3 coins Optimal → 3 + 3 = 2 coins ✔
Greedy works for "canonical" systems like {1, 5, 10, 25} or ₹{1, 2, 5, 10} but fails for arbitrary denominations.

🧭 More places where greedy fails

  • Travelling Salesman: nearest-neighbour tour can be far from optimal.
  • Shortest paths with negative edges: Dijkstra (greedy) breaks; use Bellman-Ford.
  • Longest path / graph colouring: greedy gives only approximations.
  • Job scheduling with dependencies and many NP-hard problems.

✅ When does greedy work?

  • Greedy-choice property: a globally optimal solution can be reached by a locally optimal choice.
  • Optimal substructure: optimal solution contains optimal solutions of subproblems.
Examples: Fractional knapsack, Huffman coding, Kruskal & Prim MST, Dijkstra (non-negative weights), Activity selection.

Graham Scan — Convex Hull

Computational geometry O(n log n)Stack + cross product
Points 🖱 Click on the canvas to add a point
Pivot P0Stack / hullLeft turnRight turn (pop)
🪢

The rubber-band picture

Hammer nails into a board at each point, stretch a rubber band around all of them and let go. The shape it snaps into is the convex hull — the smallest convex polygon containing every point. Graham Scan finds it by walking around the points in angle order and keeping only left turns.

🪜 Algorithm Steps

  1. Pick the pivot P0: lowest y (leftmost if tie). It is surely on the hull.
  2. Sort the other points by polar angle around P0 (closer first if equal angle).
  3. Push P0 and P1 on a stack.
  4. For each next point P: while the last two stack points and P make a non-left turn, pop.
  5. Push P.
  6. When all points are processed, the stack holds the hull in counter-clockwise order.

🧭 Orientation test (cross product)

For points a → b → c:
cross = (b.x − a.x)(c.y − a.y) − (b.y − a.y)(c.x − a.x)
  • cross > 0 → counter-clockwise → left turn ✔ keep
  • cross < 0 → clockwise → right turn ✘ pop
  • cross = 0 → collinear → pop (keep only outer point)

⏱ Complexity

  • Finding pivot: O(n)
  • Sorting by angle: O(n log n)
  • Scan: every point pushed once and popped at most once → O(n)
  • Total: O(n log n), Space: O(n)
Other hull algorithms: Jarvis March O(nh), Quickhull O(n log n) avg, Andrew's Monotone Chain O(n log n).

📝 Small Example

Points: (0,0) (1,1) (2,2) (4,4) (0,3) (1,2) (3,1) (3,3)
Pivot : (0,0) Hull : (0,0) → (3,1) → (4,4) → (0,3)
Interior points like (1,1), (2,2), (1,2), (3,3) get popped because they create right turns or lie on a line.

Strassen's Matrix Multiplication

Divide & Conquer 7 multiplications instead of 8O(n2.807)
Pink = cells of A used · Cyan = cells of B used · Green = result / M used
✂️

Trade one multiplication for a few additions

Normal multiplication of two n×n matrices needs n³ multiplications. Split each matrix into four (n/2)×(n/2) blocks: the usual method needs 8 block multiplications. Volker Strassen (1969) found a clever way using only 7 — and because multiplication is much costlier than addition, doing this recursively makes the whole thing asymptotically faster.

🧩 Divide

A = | A11 A12 | B = | B11 B12 | | A21 A22 | | B21 B22 |
Each block is an (n/2)×(n/2) matrix (for 2×2 matrices each block is a single number).

✖️ The 7 products

M1 = (A11 + A22)(B11 + B22) M2 = (A21 + A22) B11 M3 = A11 (B12 − B22) M4 = A22 (B21 − B11) M5 = (A11 + A12) B22 M6 = (A21 − A11)(B11 + B12) M7 = (A12 − A22)(B21 + B22)

➕ Combine

C11 = M1 + M4 − M5 + M7 C12 = M3 + M5 C21 = M2 + M4 C22 = M1 − M2 + M3 + M6
Memory aid: C12 and C21 are the "easy" ones (2 terms); C11 and C22 use 4 terms.

⏱ Complexity

Naive : T(n) = 8T(n/2) + O(n²) → O(n³) Strassen: T(n) = 7T(n/2) + O(n²) → O(n^log₂7) ≈ O(n^2.807)

⚖️ Limitations

  • More additions and extra memory for temporary matrices.
  • Slower than naive for small n — real code switches to naive below a cutoff (e.g. n ≤ 64).
  • Less numerically stable for floating point.
  • Works on n = power of 2 (pad with zeros otherwise).

✈️

Which two planes are dangerously close?

An air-traffic radar shows n aircraft. Checking every pair needs n(n−1)/2 distance computations — O(n²). Divide & conquer does it in O(n log n): split the plane with a vertical line, solve both halves, then only check a thin strip around the line.

🪜 Algorithm Steps

  1. Sort points by x-coordinate.
  2. Divide at the middle point into left half L and right half R.
  3. Conquer: recursively find dL and dR. (≤ 3 points → brute force.)
  4. Let d = min(dL, dR).
  5. Combine: collect points within distance d of the dividing line (the strip), sort them by y.
  6. For each strip point compare with the next points whose y-difference < d (at most 7).
  7. Answer = min(d, best strip distance).

🤔 Why only ~7 comparisons?

Inside the strip, consider a d × 2d rectangle above a point. Points on the same side are at least d apart, so each d/2 × d/2 square holds at most one point → at most 8 points in the rectangle. Hence each strip point is compared with only a constant number of neighbours.
dist(p,q) = √((p.x − q.x)² + (p.y − q.y)²)

⏱ Complexity

T(n) = 2T(n/2) + O(n) → O(n log n)
(With re-sorting the strip in every call it is O(n log² n); pre-sorting by y gives O(n log n).)
