Understanding the Multi-Stack

How to run several stacks inside one block of memory without wasting space.

First, what is a stack?

A stack is a list where you can only add or remove items at one end, called the top. The last item you put in is the first one to come out. This rule is called LIFO (Last In, First Out).

🍽️

Think of a pile of plates in a canteen. You put a clean plate on the top, and the next person takes the plate from the top. Nobody pulls a plate from the middle.

So what is a multi-stack?

A multi-stack keeps two or more stacks inside a single array. Instead of giving each stack its own fixed array (and wasting space when one stack is small and another is big), all stacks borrow boxes from one common pool.

🗄️

Picture one cupboard with 10 shelves shared by three roommates. Any roommate can use any empty shelf. Each roommate just remembers which shelf holds their newest item, and each shelf has a sticky note saying where that person's previous item is.

Simple way (fixed split): divide the array into equal parts, e.g. 10 boxes for 3 stacks becomes roughly 3 + 3 + 4. Easy, but Stack 1 may overflow while Stack 3 is empty.

Two stacks special case: start one stack at the left end and the other at the right end. They grow towards each other and only overflow when the whole array is full.

Smart way (used in this demo): any stack can use any free box. We keep three helper arrays:

arr[] stores the values.
top[k] holds the box index of each stack's top.
next[] links each box to the box below it, or to the next free box.
freeTop points to the first empty box.

How Push and Pop work, step by step

Push(value) onto stack s

  1. Check for overflowIf freeTop == -1, there is no empty box left.
  2. Grab a free boxi = freeTop
  3. Move the free pointerfreeTop = next[i]
  4. Link to the old topnext[i] = top[s] so we can find the item below later.
  5. Make it the new top and storetop[s] = i; arr[i] = value;

Pop() from stack s

  1. Check for underflowIf top[s] == -1, the stack is empty.
  2. Find the top boxi = top[s]
  3. Move the top downtop[s] = next[i]
  4. Return the box to the free listnext[i] = freeTop; freeTop = i;
  5. Give back the valuereturn arr[i];

Understanding the Priority Queue

A queue where the most important item always goes first, no matter when it arrived.

What is a priority queue?

In a normal queue, the first person in line is served first. In a priority queue, every item carries a priority, and the item with the highest priority is served first. Items with the same priority can be served in any order.

🏥

A hospital emergency room. A patient with a broken leg who arrived an hour ago will wait if someone with a heart attack arrives now. Seriousness decides the order, not arrival time.

Max priority queue: the largest value comes out first. Example: 60, 50, 40, 30.

Min priority queue: the smallest value comes out first. Example: 10, 20, 30, 40.

Why use a heap?

We could keep a plain list and search for the biggest item each time, but that takes O(n). A binary heap is a complete binary tree where every parent is bigger (max-heap) or smaller (min-heap) than its children. The best item is always at the root, and both insert and remove take only O(log n).

The tree is stored in a plain array with no pointers. Box 0 is the root, and the children of box i are at 2i + 1 and 2i + 2.

How insert and extract work, step by step

Insert(x): “bubble up”

  1. Add at the endPlace x in the next empty box so the tree stays complete.
  2. Compare with the parentParent is at (i − 1) / 2.
  3. Swap if x is betterIn a max-heap, swap when x is bigger than its parent.
  4. RepeatKeep going up until the parent is better or x reaches the root.

Extract(): “sink down”

  1. Save the rootThis is the answer to return.
  2. Move the last item to the rootThen delete the last box.
  3. Compare with both childrenPick the better child.
  4. Swap and repeatSwap down while a child is better, then stop.

Understanding the Deque

Deque (said “deck”) is short for double-ended queue: a line you can join or leave from both ends.

What is a deque?

A deque lets you insert and delete at both the front and the rear. It combines the powers of a stack (one end) and a queue (two ends, one direction) into one structure.

🚆

A train where coaches can be attached or detached at the engine end and at the tail end. You never touch a coach in the middle.

Input-restricted deque: insert only at the rear, but delete from both ends.

Output-restricted deque: delete only from the front, but insert at both ends.

Use only one end and you get a stack. Insert at the rear and delete at the front and you get a normal queue.

Why a circular array?

If we used a plain array, pushing at the front would mean shifting every item right, which costs O(n). A circular array treats the last box as sitting right next to the first box. Moving front one step left from box 0 simply wraps around to box 7. The modulo operator % does the wrapping, so every operation stays O(1).

The four operations, step by step

  1. Push front(x)If full, report overflow. Otherwise move front one step left: front = (front − 1 + cap) % cap, store arr[front] = x, and increase size.
  2. Push back(x)If full, report overflow. Otherwise the rear slot is (front + size) % cap. Store x there and increase size.
  3. Pop front()If empty, report underflow. Otherwise read arr[front], move front = (front + 1) % cap, and decrease size.
  4. Pop back()If empty, report underflow. Otherwise the last item is at (front + size − 1) % cap. Read it and decrease size.
